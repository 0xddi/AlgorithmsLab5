# GraphLab — структура проекта

> **Назначение файла:** карта проекта для быстрого погружения, поддержки и развития.  
> При добавлении новых файлов, вкладок, алгоритмов или форматов обновляйте этот документ.

## 1. Кратко о проекте

**GraphLab** — учебно-демонстрационное десктопное приложение на **C# + Avalonia UI 12 / .NET 9**.
Одно окно, четыре вкладки — по одному заданию на каждую. Везде есть визуальный редактор графа,
сохранение/загрузка, пошаговая демонстрация алгоритма с анимацией и журнал операций.

| Вкладка | Задание | Алгоритм | Визуализация |
|---|---|---|---|
| 1. Обход графа | Редактор графа, BFS/DFS | Обход в ширину / глубину | Очередь/стек, дерево обхода, порядок посещения |
| 2. Максимальный поток | Транспортная сеть | Эдмондс–Карп | Остаточная сеть, дополняющие пути, узкое место, min-cut |
| 3. Остовное дерево | MST | Краскал / Прим (+ max-режим) | Компоненты, рассматриваемые/принятые/отклонённые рёбра |
| 4. Кратчайший путь | Дейкстра | Выбор пользователем | Расстояния `d(v)`, дерево предков, маршрут, таблица |

## 2. Быстрый старт

```bash
cd C:\Projects\VibeCoding\graphLab
dotnet restore
dotnet build
dotnet run
```

Требования:

- .NET SDK 9.0+ (проверено на 10.0.201, target `net9.0`);
- Windows / Linux / macOS (Avalonia Desktop);
- пакеты `Avalonia` 12.1.2, `Avalonia.Desktop`, `Avalonia.Themes.Fluent`, `Avalonia.Fonts.Inter`.

Сборка: `GraphLab.csproj` → `bin/Debug/net9.0/GraphLab.exe`.

> Интерфейс собран в дизайн-сетке 1440×900 и обёрнут в `Viewbox`, поэтому целиком помещается
> в окно при любом DPI/разрешении и корректно масштабируется.

## 4. Архитектура и поток данных

```text
Algorithm.Build(graph, параметры)
        │  возвращает список AlgorithmStep
        ▼
PlaybackEngine.Load(steps)  ── DispatcherTimer ──►  Current step
        │                                              │
        ▼                                              ▼
Page code-behind (ApplyStep)                    PlaybackBar (UI состояния)
   ├─ GraphView.SetVisual(step.Visual)          ├─ прогресс/позиция
   ├─ JournalPanel.SetEntries(...)              ├─ кнопки и скорость
   ├─ ResultText / таблица                      └─ слайдер
   └─ CanvasHint
```

Ключевой принцип: **алгоритмы не рисуют и не трогают UI**. Они только строят
иммутабельные (по смыслу) шаги `AlgorithmStep`. Страница применяет шаг к холсту и панелям.
Поэтому можно свободно перематывать шаги назад и вперёд — каждый шаг содержит полный снимок
визуального состояния.

### 4.1. Модель графа

`GraphNode` — `Id`, `Label`, координаты `X/Y` в мировых координатах `1000×660`.
`GraphEdge` — `Id`, `From`, `To`, `Weight`, `Capacity`, `Flow`.
`GraphModel` — списки узлов/рёбер, флаг `Directed`, событие `Changed`, методы
`AddNode/AddEdge/Remove...`, обход соседей, `Clone()`.

Для задач 1, 3, 4 используется `Weight`, для задачи 2 — `Capacity` (поток `Flow` живёт
только во время демонстрации и сбрасывается при редактировании).

### 4.2. Шаг и визуальные состояния

`AlgorithmStep`:

- `Title`, `Description` — для журнала;
- `Hint` — подсказка на холсте;
- `Metrics` — строка результата (например, «Макс. поток: 23»);
- `Visual` (`StepVisual`) — подсветки;
- `Table` — таблица (MST-рёбра / расстояния Дейкстры).

`StepVisual` содержит множества `Guid`:

| Поле | Значение | Цвет на холсте |
|---|---|---|
| `ActiveNodes` / `ActiveEdges` | текущий шаг | янтарный, пульсация |
| `VisitedNodes` | посещено/зафиксировано | зелёный |
| `FrontierNodes` | очередь/стек/граница | фиолетовый |
| `PathNodes` / `PathEdges` | итоговый путь | бирюзовый + частицы |
| `AcceptedEdges` | дерево/BFS-рёбра/улучшение | зелёный |
| `RejectedEdges` | цикл/неудачная релаксация/min-cut | красный пунктир |
| `BackEdges` | обратные дуги остаточной сети | фиолетовый пунктир |
| `NodeBadges` | `#1`, `d=2`, `C1`, `✓8` и т.п. | подпись под вершиной |
| `NodeTags` | `S`, `T` | бейдж над вершиной |
| `EdgeLabels` | «поток/пропускная способность» | подпись на ребре |

### 4.3. Воспроизведение

`PlaybackEngine` — общий для всех вкладок:

- `Load(steps)`, `Clear()`, `Play/TogglePlay`, `Pause`, `Next`, `Previous`, `Reset`, `GoTo(index)`;
- скорость `0.5× / 1× / 1.5× / 2×`, таймер `DispatcherTimer`;
- события `Changed`, по которым `PlaybackBar` обновляет кнопки/слайдер/позицию.

Кнопки на каждой вкладке: **⏮ Сначала · ◀ Шаг назад · ▶ Пуск / ⏸ Пауза · Вперёд ▶**,
слайдер перемотки, выбор скорости. `Space` переключает пуск/паузу активной вкладки
(если фокус не в текстовом поле).

## 5. Вкладки и файлы

### Задание 1 — `Views/GraphEditorView`
- Алгоритм: BFS/DFS (`TraversalAlgorithms`), стартовая вершина, порядок соседей (метка/вес).
- Полный редактор: режимы «Выбор», «+ Вершина», «+ Ребро», «Удалить»; перетаскивание;
  инспектор; направленность; три раскладки; пример; очистка.
- Матрица смежности: отображение + редактирование + «Применить», импорт/экспорт CSV.
- Файлы: JSON-граф; CSV-матрица.

### Задание 2 — `Views/MaxFlowView`
- Транспортная сеть (ориентированная), источник/сток.
- `MaxFlowAlgorithms`: BFS по остаточной сети, восстановление пути, узкое место,
  увеличение потока, финальный min-cut.
- Метки рёбер: `flow/capacity`; обратные дуги — фиолетовые, разрез — красные.
- Файл: JSON-сеть (потоки при загрузке обнуляются).

### Задание 3 — `Views/MstView`
- `SpanningTreeAlgorithms`: Краскал (сортировка + DSU) и Прим; режим min/max.
- Таблица выбранных рёбер и суммарного веса, журнал шагов.
- Файлы: JSON-граф и JSON-остовное дерево (дерево сохраняется как подграф;
  загрузка показывает его на холсте).

### Задание 4 — `Views/ShortestPathView`
- `ShortestPathAlgorithms`: Дейкстра; старт и цель выбирает пользователь.
- Таблица `вершина / d(v) / предыдущая / статус`, дерево предков, анимация маршрута.
- Проверка неотрицательных весов; обработка недостижимой цели.
- Файл: JSON-граф.

## 6. Форматы файлов

### 6.1. JSON-граф

```json
{
  "version": 1,
  "kind": "graph",
  "directed": false,
  "nodes": [
    { "id": "guid", "label": "A", "x": 170, "y": 160 }
  ],
  "edges": [
    { "id": "guid", "from": "guid", "to": "guid", "weight": 4, "capacity": 4 }
  ]
}
```

- `kind` может быть `graph` или `mst`;
- координаты клампятся в рабочую область;
- при отсутствии координат применяется круговая раскладка;
- некорректные/висячие рёбра пропускаются при загрузке.

### 6.2. CSV-матрица смежности (задание 1)

Экспорт:

```csv
,A,B,C
A,0,5,0
B,5,0,7
C,0,7,0
```

- первая строка и первый столбец — метки (могут отсутствовать);
- `0` — ребра нет, иначе вес;
- для неориентированного графа матрица обязана быть симметричной;
- петли (ненулевая диагональ) не поддерживаются;
- парсер понимает запятую и точку с запятой, кавычки CSV.

## 7. Управление холстом

| Действие | Результат |
|---|---|
| Режим «Выбор» + клик по вершине | выбрать; перетаскивание — перемещение |
| Режим «Выбор» + клик по ребру | выбрать ребро в инспекторе |
| «+ Вершина» + клик по пустому месту | добавить вершину с автоматической меткой |
| «+ Ребро» + две вершины | создать ребро со значением из панели |
| «Удалить» + клик | удалить вершину/ребро |
| `Delete` / `Backspace` | удалить выбранное |
| `Esc` | отмена создания ребра / снять выделение |
| Колесо/панорама | не используется: сцена автоматически вписывается в размер холста |

Любое изменение графа сбрасывает построенный сценарий и показывает об этом сообщение
в журнале — нужно построить заново.

## 8. Как расширять

### Новый алгоритм для существующей вкладки

1. Добавьте статический класс в `Algorithms/`.
2. Сформируйте `List<AlgorithmStep>`: для каждого шага заполните `StepVisual`,
   `Title`, `Description`, `Hint`, `Metrics`.
3. В соответствующем `*View.axaml.cs` добавьте пункт выбора и вызов.
4. Обновите теорию и `PROJECT_STRUCTURE.md`.

### Новая вкладка

1. Создайте `Views/MyTaskView.axaml(.cs)` по образцу существующих.
2. Подключите `GraphToolbox`, `GraphInspector`, `PlaybackBar`, `JournalPanel`.
3. Добавьте `<TabItem>` в `MainWindow.axaml`.
4. Зарегистрируйте задачу в таблице раздела 1 и опишите управление.

### Новое визуальное состояние

1. Добавьте поле в `StepVisual` и клонирование в `Copy()`.
2. Обработайте его в `GraphView.DrawNodes`/`DrawEdges`.
3. Задокументируйте цвет в разделе 4.2.

## 9. Ограничения и идеи развития

- Петли и параллельные рёбра не поддерживаются (редактор их не создаёт).
- Нет undo/redo и контекстного меню — удаление через режим/инспектор/`Delete`.
- Дейкстра работает только с неотрицательными весами; для отрицательных нужен Беллман–Форд.
- MST сохраняется как обычный граф с флагом `kind: "mst"`; отдельный просмотр дерева — идея на будущее.
- Для потоков можно добавить визуализацию «остаточной сети целиком», а не только пути.
- Возможные улучшения: экспорт PNG, темы, сохранение сценария шагов, озвучка/тултипы.
